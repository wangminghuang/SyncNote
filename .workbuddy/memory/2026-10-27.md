## SyncNote 项目初始化完成

**需求**：原生 Android app，输入 GitHub 仓库链接 + 选择本地目录 + 同步按钮，把仓库 clone/更新到手机本地目录（如 `.../tmp/Notes`）。

**技术选型（已定）**
- Kotlin + Jetpack Compose，包名 `com.example.syncnote`，minSdk 26 / targetSdk 37 / compileSdk 37
- Git 引擎：JGit `5.13.3.202401111512-r`（5.x 而非 6.x，后者依赖 Java 11 API 在 Android 上易编译失败）
- minSdk 必须 ≥ 26：JGit 用到 `java.nio.file`，该包 API 26 才引入
- 目录访问：`MANAGE_EXTERNAL_STORAGE`（所有文件访问权限）拿真实 File 路径给 JGit 写；不用 SAF，因为 `content://` URI JGit 不接受
- 同步语义：目录无 `.git` → clone（浅克隆 setDepth(1)）；已有 `.git` → fetch + reset --hard origin/HEAD

- Android SDK: `D:\android-studio-sdk`

- 新模板无 `org.jetbrains.kotlin.android` 插件（AGP 9 内置 Kotlin 支持），不要手动加
- `INTERNET` 权限模板不生成，必须手写进 manifest

## 13:08 修复「改了仓库地址仍拉旧仓库」

**问题**：`update(url, ...)` 的 `url` 参数是死参数。`fetch().setRemote("origin")` 用的是
`.git/config` 里已存的地址，导致用户把输入框改成另一个仓库时，程序仍去拉旧仓库并
`reset --hard` 成旧内容，表面上还显示"同步成功"。

**修法**：fetch 前读出 `remote.origin.url` 并与传入地址比对（`normalizeRepoUrl()` 归一化，
忽略协议 / userinfo / `.git` 后缀 / 结尾斜杠 / 大小写）：
- 缺失 → 直接写入
- 归一化后不同 → 直接报错，提示该目录已是另一仓库的副本
- 仅是写法不同 → 静默改写成新写法

**拉取原理备忘**（回答用户提问时整理）：`fetch`（refspec `+refs/heads/*:refs/remotes/origin/*`
带 `+` 允许非快进，`setRemoveDeletedRefs(true)` 清理已删分支，只动 refs/remotes 不动工作区）
→ `resolveDefaultBranch()`（origin/HEAD → main/master → 字典序）→ `reset --hard`
（HEAD + 索引 + 工作区三者同改，无冲突）→ `clean -d`（不调 `setIgnore(true)`，
`.gitignore` 覆盖的文件保留）。

构建：`assembleDebug` BUILD SUCCESSFUL in 16s。
